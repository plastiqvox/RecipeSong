# 내 플리 아티스트와 놓친 앨범

상단 **내 플리 아티스트** 탭에서 직접 만든 플레이리스트의 곡을 아티스트별로 모아 본다. 플리는 좋아하는 곡을 추린 목록으로 취급한다. 전체 라이브러리를 좋아하는 아티스트 목록으로 바꾸거나 추천 점수를 변경하지 않는다.

- 기본 출처는 모든 직접 만든 플리의 합집합이다. 시스템·스마트 목록과 폴더는 제외한다. 특정 플리를 선택할 수 있다.
- 여러 플리에 같은 곡이 있어도 아티스트·앨범·곡명 기준으로 한 번만 센다. 플리 곡의 기존 취향 가중치(`TrackRecord.Weight`) 합이 높은 순으로 정렬한다. 좋아요·별점·재생 수를 반영하며 기존 계산의 스킵·최근성 보정도 적용한다. 동점이면 좋아요 곡 수 → 누적 재생 수 → 플리 곡 수 → 이름순이다. 재생 수는 가중치에서 포화되므로 그 이상은 동점 비교에 반영한다. 목록에 좋아요 곡 수와 재생 수도 표시한다.
- **팔로우 포함**을 켜면 등록한 아티스트도 함께 표시한다. 플리에 곡이 없는 팔로우는 0곡으로 표시한다.
- 컴필레이션의 Various Artists는 곡의 아티스트로 묶는다. 내 곡 펼치기, 아티스트 이름 필터, 목록 새로고침을 제공한다.
- 아티스트 썸네일은 전체 라이브러리에서 해당 아티스트의 앨범별 누적 재생 수를 합산해 상위 3개 앨범 커버를 가로로 표시한다. 앨범이 1~2개면 있는 만큼 표시한다. 중복 곡은 한 번만 세며 동점은 곡 수·앨범명으로 정한다. 각 썸네일 도움말에 앨범명과 재생 수를 표시한다. 재생 이력이 전부 0인 경우에도 같은 동점 기준을 사용한다.
- 썸네일은 보이는 행부터 순차 조회하고 음원 내장 커버 → 기존 Deezer·iTunes 조회와 캐시를 재사용한다. 라이브러리 앨범이 없는 팔로우나 커버 조회 실패는 음표로 표시한다. 새로고침·종료 시 이전 조회를 취소하며 플리·검색어 필터 변경 시 같은 커버 조회를 재사용한다.

목록 새로고침은 설정된 라이브러리 원본을 다시 읽는다. iTunes XML을 쓰는 경우 iTunes에서 변경한 플리를 XML로 내보내야 반영된다.

## 놓친 앨범 찾기

아티스트를 선택하면 Deezer 이름 검색 후보를 **전체 라이브러리의 보유 앨범·곡명**과 비교한다. 보유 앨범 상위 3개의 앨범 검색에서도 같은 아티스트명·앨범명을 가진 ID를 보충하므로 이름 검색 앞부분에 올바른 동명이인이 없어도 찾을 수 있다.

- 일반적이지 않은 서로 다른 앨범 2개가 일치하거나, 같은 앨범 안의 서로 다른 수록곡 2개가 일치하는 후보를 확인한다. 디럭스·리마스터 등 같은 앨범의 판본은 한 앨범으로 묶는다. 짧거나 일반적인 제목·Intro·Outro 등은 자동 판정 근거에서 제외한다.
- 조건을 만족하는 후보가 하나이고 다른 후보의 조회도 완료됐을 때만 자동 선택한다. 후보마다 보유 앨범·곡명 일치 수를 표시한다. 앨범 근거가 충분하면 곡 대조를 생략하고 곡 일치 수도 표시하지 않는다. 후보가 여럿이거나 근거 부족·조회 실패이면 자동 선택하지 않고 직접 고르게 한다. 팬 수나 검색 순위로 ID를 확정하지 않는다.
- ID를 확정하지 못했지만 검색 후보가 있으면 **아티스트 ID 후보** 목록을 바로 펼쳐 이름·ID·보유 정보 일치 수를 보여 준다. 행을 직접 선택한 뒤 **놓친 앨범 찾기**를 누른다. 자동으로 확정된 경우에는 기존 선택 상자에서 후보를 바꿀 수 있다. 검색 후보 자체가 없으면 목록을 만들지 않고 찾지 못했다는 안내를 표시한다.
- 일반 추천·놓친 앨범 찾기는 캐시 폴더의 `artist-identities.sqlite3`를 공유한다. 아티스트명·Deezer ID·선택 출처·앨범/곡 일치 근거·확인 시각을 저장한다. 앱을 다시 열어도 유지한다. Microsoft.Data.Sqlite와 함께 배포되는 SQLite 라이브러리를 사용하므로 별도 DB 서버 설치는 필요 없다.
- 후보를 직접 선택하면 즉시 수동 ID로 저장한다. 수동 ID는 자동 대조가 덮어쓰지 않으며 보유 앨범이 늘어나도 유지한다. 자동 ID는 보유 앨범·곡명 지문이 같고 확인 후 90일 안일 때만 재사용한다. 재생 수·좋아요 변경은 지문을 바꾸지 않는다. 라이브러리 앨범이 없는 팔로우는 명시 ID를 유지한다.
- **ID 다시 찾기**는 선택한 아티스트의 DB ID를 삭제한 뒤 재대조한다. 이전 백그라운드 조회가 ID를 되살리지 않도록 아티스트별 세대 번호로 저장을 검증한다. 일반 **다시 계산**은 ID를 삭제하지 않으며, DB 버전이 달라지면 다음 계산에서 후보 풀을 다시 만든다. 저장된 기간별 추천은 다시 계산할 때 갱신된다.
- 기존 `deezer-artist-ids.json`·`deezer-playlist-artist-ids.json`은 한 번만 가져와 재대조 힌트로 보관한다. 검증된 자동/수동 ID로 승격하지 않고 원래 파일도 삭제하지 않는다. 조회 실패나 미확정 결과는 확정 ID로 저장하지 않는다. 최초 DB 전환 시 아티스트를 다시 확인하므로 처음 계산은 오래 걸릴 수 있다.

라이브러리에 근거가 없는 외부 아티스트의 이름 검색 결과는 별도 `Lookup` 출처로 저장하며, 보유 아티스트의 확정 ID로 사용하지 않는다. SQLite 접근 라이브러리는 [Microsoft.Data.Sqlite](https://www.nuget.org/packages/Microsoft.Data.Sqlite/10.0.14)를 사용한다.

선택한 ID를 확인한 뒤 **놓친 앨범 찾기**를 누른다. 조회는 선택한 아티스트에 한해서 수행하며 전체 디스코그래피 페이지를 읽는다. 미래 발매일의 앨범은 제외한다. 이 대조는 동명이인 오선택을 줄이는 보조 근거이며, 제공처가 여러 아티스트를 한 ID로 합쳤거나 메타데이터가 잘못된 경우까지 보장하지 않는다.

보유 여부는 플리가 아닌 **전체 라이브러리**의 아티스트·앨범명과 비교한다.

- **미보유**: 일치하는 앨범명이 없다.
- **일부 보유**: 같은 앨범명이 있지만 라이브러리의 서로 다른 곡명 수가 카탈로그 전체 곡수보다 적다. 누락 곡 확인용으로 목록에 남긴다.
- **보유 가능성 있음 · 다른 판본**: 디럭스·리마스터 등의 판본 접미사를 뺀 제목이 일치한다. 자동으로 보유 처리하지 않는다.
- 같은 제목이며 전체 곡수 이상이 있는 앨범은 목록에서 제외한다. 곡수 정보가 빠진 보유 앨범은 상세를 조회하며 확인 실패 시 오류를 표시한다.

이 판정은 라이브러리 메타데이터 기준이다. 실제 파일 존재·음질·정확한 트랙 대응을 보장하지 않으며, 같은 곡명의 여러 디스크 수록곡은 일부 보유로 보일 수 있다. 다운로드한 ZIP도 라이브러리에 등록하지 않으면 보유 판정에 포함되지 않는다.

기본 필터는 정규·EP다. 싱글·라이브·컴필레이션을 선택해서 포함할 수 있다. 라이브·컴필레이션은 형식과 제목으로 분류하므로 제공처 표기가 부족하면 누락될 수 있다.

앨범 목록에 카탈로그 커버 썸네일을 표시한다. 커버가 없거나 불러오지 못하면 음표를 표시하며 제목·발매일·보유 상태는 그대로 보인다. 기존 이미지 변환기의 축소 디코딩과 주소별 캐시를 사용한다.

앨범을 고르면 전체 수록곡을 읽어 표시한다. **Soulseek 검색·다운로드**로 기존 검색 탭에 앨범 정보를 전달한다. 다운로드는 기존 검색 결과에서 사용자가 고르는 절차를 따른다. 자동 다운로드는 수행하지 않는다.

## 검증

`Soulseek.Checks --artist-discovery`로 플리 합집합·보유 판정·판본·필터·전체 페이지 조회·실패와 취소를 검사한다. `Soulseek.UiChecks`는 별도 가짜 데이터와 HTTP 응답으로 플리 선택·앨범 선택·수록곡·검색 연결·필터 상태 및 한국어·영어의 넓은 화면과 좁은 화면을 검사한다. 실제 사용자 앱·설정·네트워크를 사용하지 않는다.
