# RecipeSong 추천 방식

RecipeSong이 기간(주·월·연)마다 신보를 고르는 방식을 정리한 문서입니다. 숫자와 규칙은 2026-10-27 코드 기준입니다.

## 한눈에 보기

```
iTunes 라이브러리 + 레시피 플레이리스트
        │
        ├─ ① 내 곡 소리 분석 (CLAP)  →  레시피·지역 분류 모델 학습
        │
        ├─ ② 후보 모으기: 내 플리 뮤지션 + Deezer 비슷한 아티스트 2단계
        │        └─ 그 기간에 나온 앨범·EP·싱글
        │
        ├─ ③ 신보 미리듣기를 같은 소리 모델로 분석
        │        └─ 레시피 · 지역 · 내 곡과 닮은 정도 · 좋아요/별로와 닮은 정도
        │
        ├─ ④ 점수 = 소리 + 연결 + 레이블 · 참여 · 형식 · 작은 아티스트
        │
        └─ ⑤ 외부 추천(AI 커넥터 · 웹진)도 Deezer로 확인한 뒤 같은 방식으로 점수
```

LLM은 ⑤의 AI 커넥터에서만 씁니다. ①~④는 모두 내 PC에서 도는 소리 모델과 통계 모델입니다.

## 1. 내 취향 데이터

### 레시피

`ml/crates.json`이 iTunes 플레이리스트를 레시피(스타일)와 지역(일본·한국·해외)에 연결합니다. 레시피 예: Club, Jazz, Rock, 일본 인디.

### 곡 가중치

곡마다 0.1~1.0의 가중치를 매겨, 많이 듣고 좋아하는 곡을 더 중요하게 다룹니다. 계산 규칙은 Python(`ml/library.py`)과 C#이 같습니다.

| 조건 | 가중치 |
|---|---|
| iTunes에서 "별로" 표시 | 0.1 |
| 하트(loved) 또는 별점 4개 이상 | 1.0 (최대) |
| 그 밖 | 0.35 + 0.65 × min(1, log(1+재생 수) / log(13)) |

"그 밖"의 곡은 아래처럼 보정합니다.
- 별점 3개면 0.8 이상으로 올리고, 별점 1~2개면 0.4 이하로 내립니다.
- 스킵이 2번 이상이면 × (1 − 0.5 × 스킵 / (재생 + 스킵))
- 마지막으로 듣거나 추가한 지 180일이 넘으면 최대 30%까지 줄입니다. 3년에 걸쳐 서서히 줄어듭니다.
- 아무리 줄어도 0.1 밑으로는 내려가지 않습니다.

## 2. 소리 모델

### 내 곡 분석

- 곡마다 25% · 50% · 75% 지점에서 10초씩 잘라 CLAP(`laion/larger_clap_general`)으로 512차원 벡터를 만들고 평균합니다. GPU에서 처음 한 번만 하고, 대상은 약 14,500곡입니다.
- iTunes에 곡이 추가되면 새 곡만 분석합니다. "iTunes에 곡이 추가되면 자동으로 다시 학습"을 켜 두면 이 과정이 자동으로 돕니다(설정 → 취향 모델).

### 레시피 · 지역 분류

- 소리 벡터에서 평균을 빼고 다시 정규화한 뒤, 로지스틱 회귀 두 개(레시피, 지역)를 학습합니다. 곡 가중치를 `sample_weight`로 줍니다.
- 정확도는 **아티스트 단위 5-fold 교차검증**으로 잽니다. 같은 아티스트의 곡이 학습과 시험에 섞이지 않게 하려는 것입니다.
- 현재 정확도는 레시피 73.1%, 지역 78.1%입니다.
- 다시 학습한 모델이 이전보다 2%p 넘게 나빠지면 이전 모델을 그대로 씁니다.

## 3. 후보 모으기

### 내 플리 뮤지션

레시피 플레이리스트에 있는 모든 아티스트입니다. 이들의 신보는 점수와 상관없이 **항상 맨 앞**에 나옵니다.

### 추가 제안

1. **시드**: 레시피 플레이리스트마다 많이 들은 아티스트를 고릅니다. 곡 가중치 합으로 순위를 매기고, 하트를 누른 신보의 아티스트도 넣습니다.
2. **1단계**: 시드마다 Deezer 비슷한 아티스트 25명을 가져와 연결 점수를 매깁니다. 점수는 시드 가중치 × (1 − 0.7 × 순위/25)입니다.
3. **2단계**: 1단계 상위 아티스트(기본 120명)마다 비슷한 아티스트 15명을 더 가져옵니다. 점수는 1단계 점수의 0.5배에서 시작합니다.
4. 연결 점수 상위 아티스트(기본 1,000명)의 디스코그래피에서 **그 기간에 나온 발매작**을 고릅니다.

### 추천 양 (추천 설정)

| 추천 양 | 후보 아티스트 | 2단계 출발 | 소리를 들을 추가 제안 | 소리를 들을 플리 뮤지션 발매작 |
|---|---|---|---|---|
| 기본 | 1,000 | 120 | 150장 | 300장 |
| 많이 | 2,000 | 200 | 300장 | 500장 |
| 최대 | 3,000 | 300 | 500장 | 800장 |

월 단위는 소리를 듣는 장수가 4배, 연 단위는 12배입니다. 그래서 한 달을 봐도 주 단위로 네 번 본 것만큼 촘촘합니다.

### 빼는 것

- 이미 라이브러리에 있는 앨범, 컴필레이션
- 차단한 아티스트·레이블. 동명이인으로 막은 Deezer 아티스트는 그 사람만 뺍니다.
- 원래 앨범이 있는 인스트루멘털 버전. "(Instrumental)", "(Inst.)" 등이 해당하고, 원래 앨범은 Deezer 디스코그래피·같은 결과·내 라이브러리에서 찾습니다.
- "아는 아티스트 빼기"를 켜면, 라이브러리에 곡이 있는 아티스트를 추가 제안에서 뺍니다.
- 별로 표시한 앨범의 아티스트는 추가 제안에서 뺍니다. 내 플리 뮤지션이면 그대로 둡니다.

## 4. 신보 듣기

신보마다 Deezer 30초 미리듣기 최대 3곡을 받아 곡마다 앞·중간·뒤 10초로 자르고, 같은 소리 모델로 분석합니다. 결과는 앨범 단위로 저장해 두고 다시 쓰기 때문에 같은 앨범을 두 번 듣지 않습니다.

| 값 | 계산 |
|---|---|
| 레시피 · 지역 확률 | 2장의 분류 모델 |
| 취향 닮음 | 내 곡 전체와의 코사인 유사도 × (0.6 + 0.4 × 곡 가중치), 가장 닮은 20곡의 평균 |
| 비슷한 내 곡 | 위에서 가장 닮은 3곡. 카드에서 내 파일로 바로 재생됩니다 |
| 좋아요 닮음 | 좋아요 목록(아래 6장) 중 가장 닮은 3개의 평균 유사도 |
| 별로 닮음 | 별로 목록 중 가장 닮은 3개의 평균 유사도 |

## 5. 점수

한 기간의 추가 제안끼리 비교한 z점수(평균 0, 표준편차 1)로 더합니다. 그래서 소리 모델이 바뀌어도 점수 비중은 그대로 유지됩니다.

```
점수 = 취향 닮음(z)
     + 2 × 레시피 어울림(확률)
     + 연결 비중 × 아티스트 연결(z, log 연결 점수)      ← 추가 제안만
     + 1.0 × 좋아요 닮음(z)
     − 1.0 × max(0, 별로 닮음(z))
     + 1.0 × 좋아하는 레이블(0~1)
     + 0.6   좋아하는 아티스트가 수록곡에 참여했으면
     + 형식 가산점(앨범 / EP / 싱글)
     + 작은 아티스트 우대                              ← 추가 제안만
```

| 항목 | 내용 |
|---|---|
| 연결 비중 (모험 정도) | 익숙하게 1.0 · 보통 0.5 · 새롭게 0.0 |
| 좋아하는 레이블 | 가중치 제곱 합 상위 300개 앨범의 레이블을 Deezer에서 확인해 레이블별 √(합/최대)로 매깁니다. 메이저·유통사는 뺍니다 |
| 형식 가산점 | 내 라이브러리에서 앨범·EP·싱글을 듣는 비율 |
| 작은 아티스트 | Deezer 팬 5천 명 미만 +0.4, 5만 명 미만 +0.2, 100만 명 초과 −0.2 |
| 소리를 못 들은 앨범 | 미리듣기가 없으면 −1에서 시작해 뒤로 갑니다 |

## 6. 레시피 · 지역 배정

| 순서 | 대상 | 지역 결정 방법 |
|---|---|---|
| 1 | 내 플리 뮤지션 | 그 플레이리스트의 레시피·지역 |
| 2 | AI·웹진이 지역을 알려 준 경우 | 그 힌트 |
| 3 | 그 밖 | 이름 문자 → MusicBrainz(캐시, 초당 1회 제한) → 소리 모델 추정. 소리 모델 추정은 80% 이상 확신할 때만 씁니다 |

지역을 정한 뒤 레시피는 이렇게 나눕니다.
- 한국 신보는 **한국음악** 레시피로 갑니다.
- 해외 신보는 Deezer 장르로 해외 인디·얼터 / 해외 일렉트로닉 / 해외 소울·힙합 / Jazz로 나눕니다.
- 일본 신보는 소리 모델이 고른 레시피로 갑니다.

## 7. 앱에서 남기는 신호

모델을 다시 학습하지 않고, **누르는 즉시 다음 분석부터** 좋아요·별로 목록에 반영됩니다.

| 행동 | 반영 |
|---|---|
| 앨범 하트 · 곡 하트 | 좋아요 목록 (닮은 신보 +) |
| 미리듣기를 2곡 이상 끝까지, 넘긴 것보다 훨씬 많이 | 은근한 좋아요 |
| 별로(👎) | 별로 목록 (닮은 신보 −), 그 아티스트는 추가 제안에서 뺍니다 |
| 미리듣기를 2번 이상 바로 넘기고 끝까지 들은 적 없음 | 은근한 별로 |
| 차단 — 소리 때문(전반적 취향 · 보컬 · 장르 · 사운드) | 빼고, 그 앨범을 별로로 학습 |
| 차단 — 다른 이유(동명이인 · 이미 앎 · 너무 유명 · 너무 잦은 발매 · 재발매 위주 · 가사·언어 · 음악 외적 · 기타) | 빼기만 합니다. 동명이인은 그 Deezer 아티스트만 막습니다 |
| 저장함(북마크) | **반영하지 않습니다** (위시리스트 전용) |

차단을 풀면 그 차단으로 들어간 학습 신호도 같이 빠집니다.

## 8. 외부 추천

| 출처 | 가져오는 방식 |
|---|---|
| AI 커넥터 (Claude · GPT) | 웹 검색으로 그 기간의 신보를 찾습니다. 직접 입력한 API 키를 쓰고, 예산 한도 안에서만 돕니다 |
| 웹진 RSS | Pitchfork, The Quietus, Aquarium Drunkard, Bandcamp Daily, Stereogum. 6시간마다 새 글만 읽습니다. 국내 웹진은 RSS를 막아 두었거나 제공하지 않아서 없습니다 |

두 출처 모두 "아티스트 – 앨범"을 Deezer에서 확인합니다. 확인 순서는 검색 상위 10개 → 그 아티스트 디스코그래피에서 같은 제목 → 기간 안의 발매작입니다. 확인한 것만 일반 추천과 같은 방식으로 점수를 매기고, 확인 못 한 것은 뺍니다. 카드에는 배지가 붙습니다(Claude 오렌지 / GPT 초록 / 웹진 보라).

## 9. 저장과 다시 보기

- **분석 결과 저장**: 기간 · 지역 · 추천 설정마다 저장합니다. 지난 기간은 저장 결과를 그대로 쓰고, 끝난 지 7일이 안 된 기간은 12시간만 씁니다. "다시 분석"을 누르면 새로 계산합니다.
- **정밀 분석**: 연은 월 단위로, 월은 주 단위로 하나씩 분석해 합칩니다. 월이나 연 결과가 있으면 그 안의 주는 잘라서 바로 보여 줍니다.
- **NEW**: 어느 기간에서든 화면에 처음 나온 앨범에 붙고, 앱을 끌 때까지 유지됩니다. 달력에서는 아직 화면에서 보지 않은 앨범이 있는 날에 점을 찍습니다.

## 10. 실험 중 (아직 앱에 넣지 않음)

### 소리 모델 비교

같은 13,996곡으로 비교한 결과입니다.

| 소리 모델 | 레시피 | 지역 |
|---|---|---|
| CLAP (현재) | 73.1% | 78.1% |
| Discogs-EffNet (장르판) | 72.1% | 73.2% |
| CLAP + EffNet | 73.9% | 80.0% |

- EffNet은 MTG(Essentia) 연구실의 모델로, Discogs 스타일 400개를 학습했습니다. ONNX로 CPU에서 돌고, 라이선스는 CC BY-NC-SA(개인용)입니다.
- 유사도를 목표로 학습한 판(`discogs_multi_embeddings`)은 분석 중입니다.

### 앨범 커버 (CLIP)

앨범 4,615장으로 시험했습니다.

| 쓴 정보 | 레시피 | 지역 | 좋아하는 앨범 가려내기 (AUC) |
|---|---|---|---|
| 커버만 | 46.9% | 72.4% | 0.553 |
| 소리만 | 78.9% | 83.2% | 0.675 |
| 소리 + 커버 | 80.1% | 87.6% | 0.676 |

- 커버는 지역 판정에 도움이 됩니다. 특히 한국이 72%에서 77%로 오릅니다.
- 레시피와 취향에는 거의 도움이 안 됩니다.
- 다만 라이브러리 안의 앨범은 이미 직접 고른 것이라, 취향 시험에서 커버 효과가 작게 나왔을 수 있습니다. 앱에서 신보에 남긴 하트·별로가 쌓이면 다시 시험합니다.
