# 저장 공간과 캐시

## 보존하는 데이터

- `%LOCALAPPDATA%\RecipeSong` 또는 설정에서 고른 경로: 추천 기록, 좋아요·별로·팔로우, 아티스트 ID, 앨범아트 등.
- `ml/data`: 내 곡·발매작 소리 벡터와 취향 모델. 다운로드 캐시 정리로 지우지 않는다.
- `ml/.venv`: 실제 소리 서비스 실행 환경. 패키지 다운로드 캐시와 별개이며 제거 프로그램에서 삭제한다.

## 다시 받을 수 있는 캐시

설치된 앱은 기본적으로 `%LOCALAPPDATA%\RecipeSong-download-cache`를 쓴다. 저장소에서 실행하면 `ml/.download-cache`를 고정 경로로 쓴다. 개발용 캐시도 자동으로 비우지 않는다.

- `uv`: Python 패키지 설치·업데이트에 재사용하는 캐시.
- `models`, `hf`: 새로 다운로드한 Hugging Face 모델과 관련 파일.
- `temp`: 설치 한 번의 임시 작업. 성공·실패 후 해당 작업 폴더만 지운다.

소리 서비스와 설치 스크립트는 같은 전용 경로를 사용한다. 이전 공용 uv·Hugging Face 캐시는 건드리지 않는다. 이미 받은 공용 소리 모델의 완전한 스냅샷은 그대로 읽어 중복 다운로드를 줄인다. 공용 캐시의 크기는 이 앱 전용 용량 합계에 포함되지 않는다.

## 설정에서 관리

**설정 → 저장 위치와 용량 → 패키지·모델 캐시**에서 전용 경로와 용량을 확인한다.

- 위치 변경은 다음 실행 때 완료한다. 임시 대상에 복사를 마친 뒤 경로 설정을 저장하고 원본 다운로드 캐시를 비운다. 복사 실패 시 원본을 보존한다.
- 비우기는 확인 후 다음 실행에 수행한다. 모델·패키지를 다시 받을 수 있으며, 취향 모델·곡 분석 결과·추천 기록은 보존한다.
- 예약은 재실행 전에 취소할 수 있다. 다른 프로세스가 캐시를 사용하는 동안 이동·비우기를 차단한다.
- 앱 소유 표식이 없는 기존 데이터 폴더, 드라이브 루트, 상위·하위 폴더 및 연결된 폴더로의 이동을 허용하지 않는다. 위치 선택 시 `RecipeSong-download-cache` 하위 폴더를 사용한다.
- 앱을 제거해도 다운로드 캐시는 자동으로 삭제하지 않는다. 다시 설치하거나 개발할 때 재사용할 수 있다.

## 설치 여유 공간

소리 분석 환경 첫 설치 전 실행 환경 드라이브 약 6GiB, 다운로드 캐시 드라이브 약 8GiB를 확인한다. 같은 드라이브이면 약 14GiB가 필요하다. 실제 다운로드 크기와 설치·압축 해제 중 필요한 여유 공간은 다르다. 이미 PyTorch·Transformers가 설치된 환경의 업데이트는 설치 스크립트에서 더 작은 여유 공간을 확인한다.

인스톨러 파일 복사 전과 소리 환경 설치 전 검사한다. 설치 작업만의 임시 폴더는 지우지만 재사용할 패키지·모델 캐시는 남긴다. 전용 캐시 바깥의 예전 검증 출력은 자동으로 삭제하지 않는다.

## 개발 검증

검증 빌드는 작업마다 새 폴더를 만들지 말고 고정 경로를 재사용한다. 실행 중인 사용자 앱의 출력 폴더는 덮어쓰지 않는다.

저장소의 소리 환경도 같은 개발 캐시로 설치하려면 저장소 루트에서 아래처럼 실행한다. 직접 `uv sync`를 실행하면 uv의 공용 캐시 설정을 따른다.

```powershell
./installer/setup-sound.ps1 -MlDirectory ./ml -Uv (Get-Command uv.exe).Source
```

```powershell
dotnet build tests/Soulseek.UiChecks/Soulseek.UiChecks.csproj -o ../.verify/recipesong-ui
dotnet build tests/Soulseek.Checks/Soulseek.Checks.csproj -o ../.verify/recipesong-checks
```

기존 `RecipeSong-*` 임시 검증 폴더는 일반 사용자 설치에서 생성하는 폴더가 아니다. FFmpeg 등이 빌드별로 복사되므로 개발 출력만 정기적으로 정리한다.
